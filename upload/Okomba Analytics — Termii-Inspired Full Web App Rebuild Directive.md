# OKOMBA ANALYTICS — TERMII-INSPIRED FULL WEBSITE REBUILD

## MASTER DIRECTIVE

You are now responsible for rebuilding the **entire Okomba Analytics web application** into a premium, modern, highly interactive digital-services platform.

Repository:

`https://github.com/ifeanyiokomba/okomba-analytics`

Primary visual/interaction inspiration:

`https://termii.com`

Important:

**Do NOT clone Termii's website.**

Do NOT copy:

- Termii's branding
- logo
- exact copy
- exact sections
- illustrations
- proprietary product language
- proprietary animations
- exact page structure

Instead, reverse-engineer the **design principles and interaction philosophy** that make Termii's website feel premium, then rebuild those principles around **Okomba Analytics' own services, audience, products, brand and business model**.

The goal is:

> **Termii-level product design quality + Okomba Analytics identity + Okomba Analytics services.**

# 1. BEFORE CODING — STUDY TERMII

First inspect the current Termii website carefully.

Study:

- typography
- font weights
- font sizes
- heading scale
- line heights
- navigation
- button treatment
- hero composition
- animated text
- typing effects
- cursor effects
- section transitions
- scroll behaviour
- reveal animations
- cards
- borders
- spacing
- whitespace
- product demonstrations
- numbers/statistics
- logos
- testimonial presentation
- case studies
- CTA design
- footer
- mobile experience

Pay particular attention to how Termii uses:

### Animated narrative

The website communicates its value through dynamic text, changing states and product-like UI rather than a static collection of paragraphs.

### Product simulation

Instead of merely saying what the platform does, the site visually demonstrates workflows such as transaction processing, verification, delivery, monitoring and recovery.

### Progressive storytelling

The visitor is taken through:

Problem → consequence → solution → proof → product → process → trust → CTA.

Adapt this storytelling structure to Okomba Analytics.

# 22. MOTION SYSTEM

Build a unified motion language.

Do not add random animations to individual sections.

Define:

### Micro

150–250ms

Buttons, icons, hover states.

### Standard

300–500ms

Cards, navigation, reveal transitions.

### Dramatic

600–1000ms

Hero and major storytelling transitions.

Use easing curves consistently.

Animations should feel:

**smooth → deliberate → controlled → premium**

Never:

**bouncy → cartoonish → excessive**

# 29. PERFORMANCE
